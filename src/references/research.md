# Research

Investigate a question against high-trust sources and capture the findings as a Markdown file in the repo. The reading is delegated so the session keeps moving.

1. **Scope it** with one grilling round: the question, what proof settles it, where the findings file lives.
2. **Propose the output path** from the repo's own convention (wherever it already keeps such notes). If there is none, propose a sensible location and say so. Confirm with the developer before dispatch.
3. **Dispatch a background agent** and keep working; announce when it reports back.
4. **Hold the source bar.** Primary sources only: official docs, source code, specs, first-party APIs. Follow every claim back to the source that owns it and cite it inline. A secondary write-up (blog, tutorial, forum answer) may point the way but gets flagged as secondary if it ends up cited.
5. **Land the findings** as one Markdown file, then summarize them in the conversation and present 4 suggestions informed by what was learned (often: fold a finding into the plan, or start the work it unblocks).
